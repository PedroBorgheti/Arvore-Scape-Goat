Projeto Pratico 1 - Scapegoat Tree

Integrantes: Maisa Vendrame Kuhne, Pedro Borgheti e Vinicios Nunes

1. Objetivo

Medir o custo da Scapegoat Tree em um banco chave-valor em memoria, usando put (insercao), get (busca) e delete (remocao).

2. Metodo

O benchmark foi escrito em C e usa clock_gettime(CLOCK_MONOTONIC) para medir apenas as operacoes. Foram usadas N = 10.000 chaves, 30.000 operacoes nas cargas mistas e alpha = 0,70. O gerador xorshift e a semente 0x12345678 tornam as chaves reproduziveis. O checksum evita que buscas sejam eliminadas pelo compilador.

4. Como reproduzir

Container Linux

Na pasta do projeto, execute:

docker build -t scapegoat-benchmark .
docker run --rm scapegoat-benchmark > resultados.csv

O Dockerfile usa a imagem gcc:13, compila com -O2 e executa o benchmark dentro de Linux.

Sem container

sh run.sh

5. Origem dos dados

Os dados sao produzidos pelo proprio programa main.c, sem fonte externa. As regras das cargas foram retiradas do enunciado do Projeto Pratico 1 - Arvores Balanceadas, UTFPR, periodo 2026.2. A implementacao da Scapegoat Tree esta em ScapegoatTree.c e ScapegoatTree.h. O arquivo resultados.csv e o registro bruto da execucao.

6. Conclusao

A insercao sequencial testa o caso de maior estresse estrutural. As cargas mistas mostram o comportamento geral do banco, enquanto leitura e escrita intensivas isolam perfis de uso diferentes. Nesta amostra, a leitura intensiva apresentou menor custo medio por operacao, enquanto a escrita intensiva foi mais custosa por envolver mais alteracoes estruturais. Os resultados devem ser comparados no mesmo ambiente, pois CPU, compilador e carga do sistema alteram os tempos.
